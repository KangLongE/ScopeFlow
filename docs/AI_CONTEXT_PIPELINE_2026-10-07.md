# AI 문맥 파이프라인 구현·검증

기준: 제공된 `ScopeFlow-AI-Context-Pipeline-Spec.md`. 기존 Next.js / Prisma / PostgreSQL / Groq 구조를 유지했다. 새로운 AI SDK, 공급자 전환, 자동 고객 승인 기능은 추가하지 않았다.

## 반영 내용

- 최초 분석, 질문, 요구사항, 작업량, Scope 설명, 변경 비교가 같은 `buildProjectAIContext`를 사용한다.
- 고객 원문과 수정 이력, 저장 Q&A, 확정 요구사항, 명시적 조건·제외, 담당자 판단, 저장 견적, 지정 승인 Scope와 변경 요청을 전달한다. 원문 이력의 전체 텍스트는 `sources`에 보존하고 참조로 연결한다. 입력이 너무 크면 생략하지 않고 거부한다.
- 실행별 입력 스냅샷·지문·프롬프트 버전·모델·기준 Scope·결과를 저장한다. 캐시 실행도 기록하고, 실패 결과를 확정 데이터에 반영하지 않는다.
- 모델을 기다리는 동안 DB 트랜잭션을 유지하지 않는다. 실행 완료와 반영 시 각각 최신 문맥을 확인하고, 반영 검사·쓰기에는 프로젝트 행 잠금을 사용한다.
- 다른 출처 ID, 실제 문장과 다른 인용, 잘못된 요구사항 ID, 기존 조건 ID의 덮어쓰기·대체 관계 변경을 거부한다. 조건 수정은 새 ID와 `supersedes`로 연결한다.
- 중요한 가정·충돌·미확정 조건은 담당자 사유와 실제 출처가 있어야 반영할 수 있다. 편집으로 경고를 지워도 원본 경고를 검사한다. 담당자 판단과 고객 승인을 구분해 감사 기록에 남긴다.
- 요구사항 반영은 추가/수정/제외/유지 제안만 적용하며, 선택하지 않은 기존 항목을 삭제하지 않는다. 답변·범위 변경 시 기존 시간과 금액은 보존하고 재검토 필요로 표시한다.
- Scope AI 설명은 저장된 작업량·단가·조정액·기간을 덮어쓰지 않는다. 알려진 최종 견적·기간 표현이 저장 수치와 다르면 설명 수정 전 반영을 막는다. 이는 제한된 수치 검사이며 일반적인 의미 검증 엔진은 아니다.
- 변경 비교·내부 검토·승인 요청·최종 고객 승인에 지정 승인 버전과 입력 최신성을 검사한다. 승인 원본을 수정하지 않고 새 버전에만 변경을 반영한다.
- 화면에 적용 기준, 출처 문장, 개별 제외, 중요 조건 처리, 미저장 답변 안내를 추가했다. 중요 조건이 남아도 편집은 가능하며 반영만 차단한다. 기존 초안은 `UNVERIFIED`로 표시해 새 분석을 안내한다.
- Groq 요청은 지원 JSON Schema 부분집합을 사용하고 실제 출처 ID를 enum으로 제한한다. 전체 Zod·출처 검증은 서버에 유지한다. 형식 오류에만 안내를 보강해 1회 재시도하며, 잘못된 JSON을 복구해 확정하지 않는다. 토큰 한도·요청 제한은 각각 413/429로 안내한다.

실제 Groq 품질 검증은 `Backend/scripts/context-quality-check.ts`로 별도 실행한다. 최종 실행 결과는 `Backend/test-results/context-quality.json`에 저장하며 Git에서는 제외한다. 실패한 호출을 성공으로 집계하지 않는다. 실제 호출 검증의 최종 상태는 아래 절에 기록한다.

## 실제 Groq 검증: 릴리스 기준 미통과

모델과 공급자 설정을 유지했다. 최초 분석은 `openai/gpt-oss-20b`, 후속 생성은 `openai/gpt-oss-120b`를 사용했다. 최종 실행의 응답 상한은 기존 설정인 6,000이다. 토큰 한도 진단용으로 이전 두 실행의 프로세스에만 3,000/2,500을 지정했으며 환경 파일은 변경하지 않았다.

- 최초 분석과 추가 질문 호출 통과.
- 요구사항 생성 3회: 같은 입력 지문으로 3회 통과. 한 페이지 구성, 고객 자료 사용, 기본 범위에 제외 기능·새 로고를 넣지 않는 조건을 검사했다.
- 작업량 생성 3회: 같은 입력 지문으로 3회 통과. 모든 항목의 Backend 시간이 0인 것을 확인했다.
- Scope 설명: 원문에 결제·회원가입·관리자·외부 연동 제외가 모두 있었지만, 실제 응답은 별도 서버·외부 연동 두 항목만 반환했다. Scope 단계의 원문 대조 규칙을 보강한 `2.5-context`에서도 재현됐다. 해당 결과를 반영·승인하지 않고 검사를 실패로 종료했다.
- 이 최종 실행의 변경 비교·승인 이후 조건 변경 단계는 Scope 검사를 통과하지 못해 실행되지 않았다. 앞선 프롬프트의 FAQ 비교 성공이나 mock 승인 테스트를 최종 실제 모델 검증의 성공으로 대신하지 않는다.
- 형식 오류, 영문 출력, 조직 토큰 한도도 관찰됐다. 배열 구조 또는 필수 `reviewNotes` 필드의 오류는 엄격 검증을 완화하지 않고 형식 안내를 보강한 1회 재시도로 처리한다. 그래도 실패하면 확정하지 않는다.

따라서 **코드·DB 보호·브라우저 검증 통과와 전체 실제 AI 품질 검증 통과를 구분해야 한다. 현재 전체 실제 AI 릴리스 기준은 미통과다.** 고객 승인 전에 담당자가 원문과 개별 제외를 직접 대조해야 한다. 모델의 의미 해석을 완전히 검증하는 기능은 명세의 별도 후속 범위이며 이번에 추가하지 않았다.

최종 프롬프트 버전은 Scope 설명 `2.5-context`, 다른 단계 `2.4-context`다. 단계별 실제 사용 버전과 지문은 DB 실행 기록에 저장된다. Groq 요청 한도는 조직 단위이며 계정별 설정을 확인해야 한다. [Groq 공식 요청 제한 안내](https://console.groq.com/docs/rate-limits).

## DB 적용

추가 파일: `Backend/prisma/migrations/0003_ai_context/migration.sql`.

프로젝트 문맥 검토, 원문 이력, 중요 질문, 요구사항 근거, 변경 분석 기준, AI 입력·결과·기준 버전 컬럼을 추가한다. 기존 고객 데이터나 승인 문서를 삭제하지 않는다.

실제 사용할 DB 환경을 먼저 확인한 뒤 Backend에서 실행한다.

```powershell
npm run db:deploy
npm run db:generate
```

이 작업에서는 사용자 개발·배포 DB에 적용하지 않았다. Vercel에 코드만 올리고 migration을 적용하지 않으면 새 컬럼 조회가 실패할 수 있다. seed/reset은 필요하지 않다. 이전 AI 초안·변경 분석은 다시 분석해야 하며, 승인 대기 중인 이전 변경은 승인 요청 회수 후 재비교한다.

## 범위·운영 주의

- 커밋·푸시·Vercel 배포는 수행하지 않았다. `.env`와 `.env.example`의 Git 제외 상태를 유지했다.
- 테스트용 DB와 결과·캡처는 ignored 폴더에 보관한다. 실제 계정·비밀번호·API 키는 이 문서에 적지 않는다.
- 이번 검증용 PostgreSQL 프로세스는 종료했다. 테스트 DB 파일·결과는 삭제하지 않고 보존했다.
- pg의 동시 query 호출에 관한 다음 메이저 버전 경고가 있으나 현재 테스트 실패는 아니다.
- 자동 저장, 일반적인 자연어 의미 검증, 모델/계정 변경 또는 요금제 업그레이드는 이 작업에 포함하지 않았다.
- React 검수 지침에 따라 중요한 경고가 편집까지 막지 않게 했고, 파생 이슈 상태와 새 초안의 편집 상태 초기화를 확인했다. 기존 CSS·폼·브라우저 기능을 재사용했다.
