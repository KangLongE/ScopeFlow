# 변경 비교 입력 초과와 수동 견적 구현 속성 보완 (2026-11-03)

## 원인

이번 `AI_CONTEXT_TOO_LARGE` / 413은 Groq 전송 전의 토큰 예산 검사에서 발생한다. 이전 수정은 중복된 최상위 데이터를 줄였지만, 답변이 늘어나면 조건·제외 항목의 동일한 인용문, 긴 출처 ID, 승인 기능과 출처의 중복 설명이 누적됐다. 입력 자체가 기본 예산에서 최소 응답 공간을 남길 수 없을 만큼 커지면 요청이 차단됐다.

수동 견적은 구현 속성을 서버에서 검증하면서 일반 기능별 폼에는 시간·근거만 제공했다. `estimate.item` 명령과 REST 견적 수정 스키마도 구현 속성을 전달받지 않았다. 요구사항에 속성이 없으면 JSON 편집으로만 후보를 보완할 수 있었다.

## 비교 입력 수정

- 모든 출처 본문·종류·리비전과 원문 이력을 그대로 보존한다. 출처 ID만 전송용 짧은 ID로 연결하고, 응답은 서버에서 원래 ID로 복원한 뒤 검증한다. 원문·설명의 문자열은 치환하지 않는다. 모르는 ID는 추정해서 연결하지 않는다.
- 조건·제외 근거가 실제 참조 출처에 정확히 존재할 때만 중복된 인용 복사본을 제거한다. 출처에 없는 인용이나 리비전이 다른 근거는 유지한다.
- 승인 기능 설명이 현재 출처의 제목·설명과 정확히 일치할 때만 해당 출처를 참조한다. 내용이 다른 승인 설명은 유지한다. 승인 숫자·제외·구현 구조와 원본 DB 문서는 변경하지 않는다.
- 비교 전용 프롬프트 `3.4-compact-comparison`으로 관련 규칙을 명시한다. 새 조건·추가 기능 제안의 nullable 요구사항 링크도 wire 스키마에서 보존한다.
- 기본 8,000 예산과 전송 전 차단을 유지한다. 환경변수나 계정 한도를 늘리지 않았으며 원문을 임의로 잘라 넣지 않는다. 저장된 입력 스냅샷·해시·검증·확인 기록은 원래 컨텍스트와 ID를 사용한다.

## 수동 견적 수정

- 기능별 일반 폼에 페이지 수, 별도 페이지, 서버 작업, 포함 유형, 자료 적용 작업을 추가했다. 기존 구현 속성 편집 UI를 재사용한다.
- 미확정 후보 → 저장 견적 → 요구사항 순으로 기존 속성과 시간·근거를 표시한다. 한 기능에 필요한 데이터만 클라이언트에 전달한다.
- 일반 명령과 REST 수정 API에서 속성을 검증·저장한다. 시간만 다시 저장해도 검토한 속성을 보존한다. 잘못된 JSON·속성은 정상값으로 강제 보정하지 않는다.
- 속성 미확인은 계속 검토 필요로 남는다. 고급 후보의 항목이 잘못된 형태여도 일반 폼으로 복구할 수 있게 했다. 미통과 후보는 확정 견적과 분리하며, 금액·권한·리비전·근거 검증은 유지한다.

## 검증

운영 실패 입력 스냅샷을 직접 확보한 것은 아니다. 기존 카페 원문에 저장 답변 4개, 확정 기능 2개, 승인 Scope·제외 조건을 서비스 코드로 만든 격리 프로젝트에서 같은 차단을 재현했다. 실제 고객 계약이나 운영 DB는 사용하지 않았다.

| 항목 | 이전 배포 코드 | 수정 코드 |
| --- | ---: | ---: |
| 입력 추정 토큰 | 8,761 | 6,582 |
| 설정된 요청 예산 | 8,000 | 8,000 |
| 결과 | 요청 전 413 차단 | 출력 공간 1,418 확보·검증 통과 |
| 보존한 출처 본문 | 19개 | 동일한 19개 |

수치는 UTF-8 직렬화 크기에 기반한 사전 추정이며 제공자의 실제 토큰 수나 과금량이 아니다. 비교 응답은 모의 응답으로 검사했다. 매우 긴 원문은 압축 후에도 차단될 수 있고, 조직의 공유 한도에 따른 429도 별도로 발생할 수 있다.

- Backend 69개·Frontend 14개 테스트 통과, 건너뜀 없음. 동일 페이지 확인 재사용·문서 동기화·승인 문서 불변성 회귀 검사도 통과했다.
- 양쪽 Production 빌드·TypeScript 검사·lint가 통과했다.
- 다중 답변 입력의 예산, 원문·리비전 보존, 출처 ID 충돌·복원, 잘못된 근거 보존, 일반 견적 폼 명령·속성 유지·불완전 값 차단을 검증했다.
- 브라우저에서 구현 속성이 누락된 수동 견적을 재현했다. JSON 영역을 편집하지 않고 페이지 수·서버 작업 등을 선택해 저장한 뒤 오류 0·경고 0·검토 필요 0으로 통과했다. 시간 4/0/1/1과 산정 근거가 유지되고 285,000원이 반영됐다.
- 실제 Groq 추가 요청은 0회다. 이전 두 요청 한도를 유지한다. 검증 화면 서버에서는 외부 Groq 전송도 차단했다.

이번 변경에는 DB 마이그레이션·새 의존성·환경변수 변경이 없다. 운영 반영 후에도 실제 Groq 변경 비교 실행의 성공 여부는 새 외부 호출 없이 검증한 범위와 구분해야 한다.
