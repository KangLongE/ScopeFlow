# ScopeFlow Credit·오류·비용 표시 UX 구현 및 검증

작성일: 2026-10-14. 기준: `ScopeFlow-Credit-Errors-UX-Spec.md`.

기존 Context Pipeline, Rule Validator, 변경 승인 금액·기간 요약 작업을 유지하면서 프론트·백엔드를 함께 수정했다. 기존 Groq 구현과 공통 폼을 재사용했고 새 의존성, 결제/환불 기능, AI SDK 전환은 추가하지 않았다.

## 확인한 기존 정책

| 작업 | 서버 Credit |
| --- | ---: |
| 최초 요청 분석 | 2 |
| 추가 질문 | 1 |
| 요구사항 생성 | 2 |
| 작업량 추정 | 2 |
| Scope 설명 생성 | 1 |
| Scope 비교 | 3 |

- 기존 AI 서비스의 단가표를 그대로 사용한다. 월 경계는 기존 UTC 월 시작이며, Workspace 전체 및 해당 Workspace 내 사용자 한도 중 더 작은 잔여량을 적용한다.
- 월 사용량은 `SUCCESS` 기록만 합산한다. 공급자 실행 실패는 `FAILED`로 저장되어 월 Credit 사용량에 포함되지 않는다. 별도의 환불 거래나 공급자 환불 확인 기능은 원래 없으며 이번에도 만들지 않았다.
- 기존 캐시 정책은 동일 Workspace·모델·프롬프트·입력의 24시간 캐시를 재사용하며 추가 Credit을 차감하지 않는다. 캐시 조회를 실제 비용 판정보다 먼저 하므로 잔여 0에서도 유효한 캐시 재사용은 가능하다. 새 실행 기록은 캐시 여부와 실제 0 Credit을 명시한다.
- 실행 중 `PENDING`의 비용을 예약량으로 함께 계산한다. 확정 실패는 예약을 해제하고, 성공은 실제 사용으로 전환한다. 공급자 호출 중에는 DB 트랜잭션을 유지하지 않는다.
- 오래된 `PENDING`은 결과/사용 상태를 확인할 수 없는 `UNKNOWN`으로 표시하지만 예약을 임의 해제하지 않는다. 프로세스 중단 등의 상황에서는 운영자가 공급자·실행 기록을 확인해야 한다. 자동 재호출·자동 환불 기능은 없다.
- 기술적으로 성공한 응답의 Rule Validator 오류나 실행 중 고객 입력 변경은 호출 실패/무료 실행이 아니다. 실제 사용량과 초안 검증/적용 가능 여부를 따로 표시한다. 편집·저장·재검증·반영은 추가 AI 호출 없이 기존 서비스로 처리한다.

## 구현 계약

### AI 실행·Credit

- `Backend/src/lib/ai/usage-policy.ts`에 기존 정책, 정책 리비전, 가용 잔여·실행 후 예상, API 비용 상태를 모았다. Frontend에는 Credit 단가표를 넣지 않는다.
- `GET /api/v1/ai/usage`는 실제 사용·예약·한도·가용량, 작업별 preview, API 비용 소계/추정 불가 건수, 안전한 사용 이력을 반환한다.
- 같은 경로의 `operation`, `projectId`, `regenerate`, 선택 `changeId` 쿼리는 해당 입력·모델의 실제 캐시를 검사한 preview를 반환한다. `executionKey` 쿼리는 로그인 사용자의 현재 Workspace 실행만 조회한다. Frontend의 `/api/ai`는 인증·선택 Workspace를 유지하는 조회 프록시다.
- 모든 공개 유료 실행 요청은 UUID `executionKey`와 조회한 `policyRevision`을 보내야 한다. 서버는 실제 권한·현재 정책·잔여를 재검사한다. 일반 요청의 정책 리비전과 0 Credit 캐시 견적 리비전을 구분하여 캐시 만료 후 비용을 몰래 올리지 않는다.
- 기존 `ai_usage`에 실행 키, 입력 fingerprint, 정책 리비전, Credit 상태, 비용 상태·단가 snapshot, 결과 전달 상태 및 안전한 오류 필드를 추가했다. `(workspaceId, userId, executionKey)` unique 제약과 Workspace advisory lock으로 판정·예약을 원자적으로 연결한다. 별도 Credit 원장 테이블은 추가하지 않았다.
- 같은 논리 실행 재전송은 기존 실행을 반환하고, 같은 키에 다른 작업/입력은 409다. 결과 조회·재전송은 기존 초안을 다시 덮어쓰지 않는다. 공급자 지연 중 초안이 수정되면 최신 편집을 보존하고 새 실행 결과는 별도 기록으로 남긴다.
- 공통 AI 버튼은 서버 preview, 부족/권한/단계 조건, 조회 재시도, 실행 중 비활성화, 실제 차감 상태를 표시한다. 응답이 불명확하면 같은 키로 조회하며 자동으로 새 유료 요청을 보내지 않는다.
- 현재 초안 대체 안내는 상시 표시하고, 편집 손실 가능성이 있을 때만 기존 확인 절차를 사용한다. 모든 실행·승인에 새 확인 모달을 넣지 않았다. 실제 실행 완료와 초안 검증 상태를 별도 영역으로 표시한다.
- 사이드바·실행 영역은 공통 서버 Credit snapshot을 사용하고, 완료/조회 후 갱신한다. 늦게 도착한 다른 preview/Workspace 응답을 새 값으로 적용하지 않는다. 임의로 2 Credit을 빼거나 조회 실패를 0으로 표시하지 않는다.

### 한국어 오류·비용·활동·이동

- 공통 폼에서 `required`, 숫자 범위·단위, 길이, 이메일/형식, 동의 조건을 유지하는 한국어 필드 검증을 사용한다. 공백만 있는 필수 텍스트와 숫자 입력 중의 `badInput`도 검사한다.
- 여러 필드 오류를 함께 표시하고 `aria-invalid`/`aria-describedby`를 연결하며 첫 오류 필드로 이동한다. 한 필드 수정 시 그 오류만 해제한다. 오류 메시지가 label 이름에 섞이지 않도록 접근성 이름을 유지한다.
- Backend Zod 오류와 필요한 서비스 오류는 안전한 필드 경로·한국어 메시지로 전달한다. 알 수 없는 서버 오류는 원시 DB/스택을 내보내지 않는다. 저장 상태 불명 문구는 확정 실패와 구분하고 입력을 초기화하지 않는다. 기존 세션·권한·링크 오류는 해당 서버 문구를 유지한다.
- Credit과 API 추정 비용(USD)은 별개다. 실행 당시 단가/사용량으로 계산된 값, 명시적 0, 단가 미설정, 사용량 누락, 과거 계산 근거 불명을 구분한다. 작은 양수는 `< $0.00001`로 표시한다.
- 혼합 기록은 계산 가능한 소계와 추정 불가 건수를 표시한다. 과거 양수 추정값은 유지하고, 근거 없는 과거 0은 무료로 확정하지 않는다. 단가 변경으로 과거 기록을 다시 계산하거나 Credit을 다시 차감하지 않는다.
- 활동 조회는 권한 범위 내 구조화된 프로젝트/요구사항/Scope/변경 요청/담당자 참조를 정규화한다. 실제 기록의 버전·요청 번호·개수를 사용하고, 의미 없는 과거 `1` 또는 임의 payload로 사건을 꾸미지 않는다. 삭제·다른 Workspace·복원 불가 대상은 안전한 문구와 링크 없음으로 처리한다.
- AI `sourceRefs`는 기존 문맥의 사람이 읽을 수 있는 근거명을 사용한다. 기본 활동 UI에서 UUID/payload를 렌더링하지 않는다. 담당자 상세 JSON 편집/진단 영역의 내부 참조는 펼쳐서 확인할 수 있으며 고객 공개 문서에는 전달하지 않는다.
- 프로젝트 탭은 개요 → 요구사항 → 견적 → Scope 문서 → 변경 요청 순서다. 기존 경로·단계 판정·승인 문서를 유지했다. 고객/사용량/설정/프로젝트별 로딩·실패·빈 결과를 구분한다.
- 대시보드 표는 중복 진입 열을 프로젝트명 링크로 통합하고 긴 제목을 줄바꿈한다. 1348px에서는 주요 열이 카드 안에 들어가도록 배치를 조정했다. 모바일은 페이지 전체가 아닌 이름 붙은 키보드 접근 가능한 표 스크롤 영역을 사용한다.

## 실행한 검증

검증 흐름: 로그인한 격리 테스트 화면 → Frontend 실행/조회 프록시 → Backend AI 서비스 → 격리 PostgreSQL 실행/캐시/예약 기록 → 서버 잔여와 초안 상태.

| 검사 | 결과 |
| --- | --- |
| Backend 타입·린트·기본 테스트·빌드 | 통과; 37개 통과, DB 전용 5개는 아래에서 별도 실행 |
| Frontend 타입·린트·테스트·빌드 | 통과; 테스트 8/8 |
| 격리 DB Context/Validator/Impact/승인/Credit 회귀 | 13/13, 실패·skip 없음 |
| 실제 Chrome 로그인 필드 오류 | 두 필수 필드 한국어 오류, 첫 오류 포커스, 이메일 수정 시 해당 오류만 해제 확인 |
| 실제 Chrome 1348px 대시보드/요구사항 | 긴 프로젝트명 링크로 진입, 주요 표 열 범위와 새 탭 순서, 94 → 예상 92 확인 |
| 실제 Chrome 모의 AI 실행과 DB 기록 대조 | 2 Credit 실행 후 잔여 92, 캐시 실제 0, 명시적 재실행 후 90; 성공/검증 오류를 구분하고 마지막 정상 초안 확인 |
| 추가 브라우저 검증 | 아래 미확인 범위 참고; 자동화 응답 지연으로 중단 |

Backend의 Groq 요청은 고정 모의 응답으로 대체했다. 실제 공급자 호출/사용자 Credit/운영 DB는 사용하지 않았다. DB 회귀는 기존 로컬 서버의 고정 격리 DB로만 제한하는 `Backend/scripts/ux-check.mjs test`로 재확인했다.

Credit 통합 검사는 실행 중 예약, 경합 한도 초과, 동일 키 재전송/다른 입력 충돌, 조회, 정책 변경, 캐시 만료 후 0→유료 견적 충돌, 성공+검증 오류, 공급자 실패, 오래된 pending, 과거 비용 불변, 실행 중 편집 보존, Workspace 격리 및 5회/10 Credit fixture를 검사한다. 승인/변경 회귀는 실제 서비스·DB 및 기존 HTTP 테스트로 함께 실행했다.

화면 테스트에서 생성한 AI 논리 실행은 3개(유료 모의 실행 2개, 캐시 1개)이며 실제 사용은 2+0+2 Credit이었다. 초기 고정 기록 6 Credit과 합쳐 10 Credit이며, 추가 화면 제어가 멈춘 뒤 DB 재조회에서도 실행 개수·사용량은 동일했다. 5회/10 Credit QA 회귀 fixture는 별도 Workspace로 구분해 검사했다.

## 운영 적용·주의사항

- `0006_credit_errors_ux` migration은 격리 로컬 DB에만 적용했다. 설정된 일반 로컬/배포 DB는 변경하지 않았다. 운영 적용 전 대상 환경/백업을 확인하고, 미적용 `0003_ai_context`~`0006_credit_errors_ux`를 Backend의 `npm run db:deploy`로 적용한 뒤 새 프론트·백엔드를 함께 배포해야 한다. migration 없이 새 코드만 배포하면 조회가 실패할 수 있다.
- 공개 유료 API 계약에 실행 키/정책 리비전이 필수로 추가됐다. 외부 호출자가 있으면 새 preview/실행/조회 계약으로 맞춰야 한다. 내부 테스트용 서비스 진입점의 optional 인자는 공개 API 필수 검사를 우회하지 않는다.
- 커밋·푸시·Vercel 배포·환경변수 변경은 실행하지 않았다. 기존 미커밋 작업을 보존했다. 테스트 계정·비밀값·로컬 fixture는 ignored `test-results`에 두며 이 문서에 자격 증명을 기록하지 않는다.
- Prisma/pg 통합 검사에서 동시 query 관련 deprecation 경고가 출력됐으나 회귀 실패는 없었다. 드라이버 교체/pg 9 업그레이드는 하지 않았다.
- 브라우저 자동화의 화면 제어/캡처가 응답하지 않아 추가 검증을 멈췄다. 사용자에게 확인창이 보이지 않는다는 답변을 받았으므로 확인창이 원인이라고 확정하지 않는다. 이후 재연결 목록/일부 상태 조회는 가능했지만 화면 제어는 계속 실패했다. 375px, 편집 손실 확인, 최신 캐시 0 preview, 실제 응답 손실 복구는 브라우저 연결 복구 후 확인해야 한다.
- 확인한 실행 전 화면은 ignored `Frontend/test-results/ui/credit-preview-desktop.png`에 보관했다. 이 캡처는 실행 전 94→92와 탭 순서의 증거이며 마지막 완료/전체 시나리오 통과 증거가 아니다.
- 개발 서버 재시작 중 남은 불완전한 `.next/dev/types` 때문에 추가 타입 검사가 일시 실패했다. 생성 파일만 ignored 루트 `test-results/credit-dev-types-interrupted-20261014`로 보관하고 공식 `next typegen`으로 다시 생성한 뒤 Frontend 타입·린트·8개 테스트·빌드를 모두 통과했다. 타입 검사 제외/무시 옵션을 추가하지 않았다. `next-env.d.ts`의 경로 변경은 Next가 생성한 빌드 타입 경로이며 사용자 선언을 추가하지 않았다.
- 검증용 Frontend/Backend 서버와 직접 실행한 격리 PostgreSQL(55436)은 중지했다. 임시 Chrome viewport는 기본값으로 복구하고 검증용 localhost 탭은 닫았다. 데이터·스크린샷·진단 캐시는 보존했다.
