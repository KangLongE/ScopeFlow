# 변경 비교 RV-002 인용·출처 연결 수정

## 확인한 원인

사용자가 제공한 네 `reviewNotes.excludedScope` 항목 모두 출처의 제외 제목을 직접 인용하지 않고 ‘계속 제외됩니다’로 풀어 썼다. 관리자 제외는 외부 서비스 연동 제외의 출처를 참조했다. 따라서 정확한 문자열 인용 검사에서 차단된 것은 정상이다. 공급자 요청 실패나 토큰 예산 문제가 아니다.

## 수정

- 새 비교 응답은 지정된 현재 승인 Scope에서 제목·버전이 정확히 일치하는 단 하나의 제외 출처로 인용과 참조를 연결한다. 이미 존재하는 같은 승인 Scope의 제외 출처를 참조한 명시 항목만 처리한다. 신규·보류·해제 항목, 알 수 없는 참조, 다른 Scope, 오래된 버전, 중복 후보는 자동 연결하지 않는다.
- 공급자 원본은 `rawResponse`로 보존하고 연결 복구는 기존 `AI_RESPONSE_RECOVERED` 감사 경로에 기록한다. 비교 처리 버전은 `3.6-approved-exclusion-evidence`로 분리한다.
- 검증은 완화하지 않는다. 알려진 승인 제외 제목에 다른 제외 항목의 전용 출처를 연결하면 정확히 복사한 문장도 차단한다. RV-002는 각 행의 `evidence`·`sourceRefs` 경로를 표시한다.
- 기존 변경 초안에는 인용문·출처 편집과 ‘승인 문서의 제외 원문 연결’을 제공한다. 수정 후 ‘검토 저장 · 서버 재검증’이 필요하며 확정 검사를 건너뛰지 않는다. AI 재실행이나 추가 Credit 사용 없이 검토할 수 있다.

## 검증 범위

- 제공된 네 행과 출처 본문을 11월 10일에 보존한 동일 승인 Scope의 Context와 대조해 재현했다. 11월 11일 실행 전체 응답은 제공되지 않았으므로 나머지 비교 필드는 재구성했다. 운영 DB에 저장된 후보를 직접 수정한 검증이 아니다.
- RV-002 네 건이 모두 해소됐다. 기존 Context의 다른 페이지 확인 경고는 그대로 남았다. 승인 문서 800,000원·8일·제외 5개와 변경 초안의 역할별 시간·추가 일수·제외 해제 목록은 보존했다.
- 모의 공급자 경로에서 추정 입력 6,671 + 응답 상한 1,329 = 8,000 토큰을 확인했다. 입력 출처를 삭제하거나 응답 스키마를 늘리지 않았다.
- HTTP 200·400 복구 경로, 다른/알 수 없는 출처, 구버전·중복 후보, 기존 인용 검사의 차단을 회귀 테스트한다. 실제 Groq 요청은 0회다.

운영 배포와 브라우저 상호작용 검증은 수행하지 않았다. 브라우저 도구의 Windows 실행 오류로 해당 검증이 불가능했다. 재현 원문·Context·로그는 Git에서 제외되는 `Backend/test-results`에만 보관한다.
