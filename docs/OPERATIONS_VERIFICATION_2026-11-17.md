실제 운영 준비 전체가 완료됐다는 판정은 아니다. 기존 운영 고객 데이터와 접속 비밀값은 유지하고, 승인된 Vercel 환경 범위·Frontend 연결 정리만 적용했다. 변경 코드는 아직 커밋·푸시·배포하지 않았다.

## 코드·통합 검증

- Backend 테스트 **87개 통과**, 통합 테스트 건너뛰기 없음. `TEST_DATABASE_URL`은 별도 로컬 테스트 DB로 한정했다. DB 전용 도구와 앱 검증 분리, 마이그레이션·런타임 DB 대상 일치 검사를 포함한다.
- Frontend 테스트 **26개 통과**.
- 두 프로젝트 운영 빌드·타입 검사·린트 통과.
- 비밀값 검사기 자체 테스트: 실제 Git 인덱스의 키 탐지, 작업 트리만 지운 우회 거절, 값 미출력 확인.
- 환경 분리 CLI: 합성 설정 세트 통과 및 같은 AI 키 재사용 거절. 실제 Vercel·Neon 세 환경의 대조 검증으로 표시하지 않는다.
- 실제 로컬·Neon Preview·운영 전환 후보의 DB 대상과 자격 증명이 서로 다름을 확인했다. 개발·Preview 인증 Secret도 서로 다르다. Vercel의 DB·인증 Secret은 Production과 Preview의 별도 항목으로 분리했다. 운영 Secret을 다시 읽는 값 대조나 Development·운영 AI 키 중복 검증은 하지 않았다.
- 로컬 환경 파일·이전 설정의 DPAPI 암호문에서 Everyone·Authenticated Users·Users에 대한 광범위 허용 ACL 규칙이 없음을 확인했다.

## Chrome 검증

로컬 테스트 계정과 격리된 회사 데이터만 사용했다.

- 소유자가 설정에서 JSON 다운로드 성공. 현재 회사 데이터만 포함됨.
- 외부 회사 Workspace 접근 **403**, 일반 멤버 내보내기 **403**, 비로그인 내보내기 **401**.
- 허용하지 않은 Origin **403**, 정확한 로컬 Origin의 CORS 사전 요청 **204**.
- 다운로드에 `private, no-store` 적용. 계정·세션·비밀번호·공유 토큰·AI 원본 진단 제외.
- 정책 초안, 운영자·문의 이메일, 서버 작업별 Credit, 가입 화면의 안내 링크 확인.
- 390px 모바일에서 가로 넘침 없음. Chrome pageerror 0건, 로컬 HTTP 5xx 0건.

캡처·다운로드·브라우저 상태·테스트 계정은 Git에서 제외된 `Frontend/test-results/design/`에 보관한다. 운영 데이터를 내보내거나 실제 AI를 다시 호출하지 않았다.

## 백업·복구 훈련

별도 로컬 테스트 DB를 암호화 백업하고, 소스와 다른 빈 로컬 DB에 복원했다. 아카이브 인증과 PostgreSQL 형식 검사를 거쳤다. 평문 덤프를 디스크에 쓰지 않았다.

- Workspace·Project·Scope·Client·User 레코드 수 일치.
- 승인 Scope 문서의 DB 지문이 모두 일치.
- 이미 데이터가 들어 있는 대상에 두 번째 복원을 시도하면 거절됨.
- 손상된 암호문·다른 키·지원하지 않는 파일·약한 키는 단위 테스트에서 거절됨.
- 실제 복구 아카이브를 사용한 Windows `pg_restore --list`의 조기 stdin 종료도 검증함.

이 로컬 복구 훈련은 합성 테스트 데이터로 수행했으며 운영 Neon 복구나 운영 자동 백업의 증명이 아니다.

## Neon 실제 적용·권한 검증

- 관리 API로 `scopeflow-db / main`, PostgreSQL 18, PITR **21,600초(6시간)**를 확인했다. 자동 스냅샷 스케줄은 비어 있고 무료 플랜이다.
- Vercel 관리 조직에서 새 프로젝트 생성은 거절됐다. 고객 데이터를 복제하는 브랜치를 만들지 않고 동일 main에 빈 `scopeflow_preview` DB를 생성했다.
- Preview DB에 기존 마이그레이션 **6개** 적용, 업무 테이블 **26개 전체 행 수 0개**. 운영 행 복사나 seed 실행 없음.
- Preview 소유 계정은 superuser·CREATEDB·CREATEROLE·neon_superuser 역할이 없다. 실제 운영 users 조회가 **42501**로 거절됐다.
- 운영 앱 전환 후보는 public DML만 가능하며 DB·스키마 생성 및 역할 관리 권한이 없다. Preview users 조회는 **42501**로 거절됐다. Vercel에는 아직 적용하지 않았다.
- 운영 백업 계정은 public SELECT만 가능하고 clients DELETE의 EXPLAIN도 **42501**로 거절됐다. 실제 삭제는 실행하지 않았다.
- Preview 앱 전용 계정의 추가 발급은 미완료다. 승인받은 임시 소유권 변경도 PostgreSQL 권한에서 거절돼 실제 소유권 변경은 없었다. Preview 전용 소유 계정을 현재 구성으로 유지한다.
- **Preview·운영 DB의 데이터 권한은 분리되지만 main의 컴퓨트와 PITR 경계는 공유한다.**

운영 public 스키마를 PostgreSQL **18.7** `pg_dump`와 읽기 전용 계정으로 암호화 백업했다. 약 278 KB 아카이브의 AES-GCM 인증과 `pg_restore --list` 검증을 통과했다. 자체 인증·고객 데이터의 public 테이블을 포함하며 관리형 `neon_auth`·플랫폼 역할은 제외한다. 키는 별도 Windows 사용자 DPAPI 파일, 아카이브는 Git 제외 백업 경로에 보관했다. 운영 데이터의 로컬 복원·외부 보관·자동 백업은 수행하지 않았다.

## 배포 전 남은 작업

1. MCP 접근 문제는 남아 있지만 로그인 Chrome으로 필요한 설정과 사용자 제공 Preview AI 키 저장을 완료했다. Frontend 항목 4개·Backend 항목 14개를 재조회했고 두 Groq 키 항목의 별도 범위·Secret 유형을 확인했다. [실제 적용 기록](VERCEL_ENVIRONMENT_CUTOVER.md)의 Preview URL 연결과 새 Preview 배포를 별도 검증한다.
2. 운영 앱 제한 계정·마이그레이션 Secret을 준비해 코드와 함께 전환한다. 세 환경의 실제 AI 키 중복도 대조한다. 개발 DB에는 운영 데이터를 복제하지 않는다.
3. 환경 태그와 Frontend 비밀 변수 정리는 저장·재조회 검증을 마쳤다. 코드 반영·운영 재배포·이전 배포 정리 후 실제 배포 환경에서 보호 장치를 검증한다.
4. 별도 백업 스케줄·외부 보관소·PC 분실 대비 키 보관과 운영 복구 절차를 확정한다. 별도 Preview 브랜치·프로젝트와 유료 복구 보존 확대는 검토 후 적용한다.
5. 운영자가 요금·해지·환불·개인정보 보유·삭제 조건을 확정한 뒤 정식 문구와 실제 기능을 일치시킨다.

실제 Groq 요청 추가 **0회**. 이전에 허용한 실제 호출 2회 한도는 변경하지 않았다.
