# UX 보완 검증 — 2026-10-19

## 반영 내용

1. 변경 승인으로 생성되는 새 Scope의 외부 연동 목록을 실제 포함 요구사항의 유형/구현 속성에서 함께 구성한다. 승인 전 검증용 예상 문서와 실제 승인 문서가 같은 함수를 사용한다. 기존 승인 버전은 수정하지 않는다.
2. 고객의 1페이지 출처, 내부 섹션 설명, `pageCount: 1` / `separatePage: false`가 일치하면 이름만으로 RV-006 경고를 반복하지 않는다. 확인 근거와 지문을 저장·표시하고 매 검증 시 현재 설명/구조/출처로 다시 판정한다. 별도 페이지·출처 소실·조건 충돌은 기존 검증을 유지한다. 규칙 버전은 1.3.0이다.
3. 견적 저장 응답은 트랜잭션 안에서 `DRAFT_SAVED` / `APPLIED` 및 해당 시점의 확정 금액을 반환한다. 완료 메시지를 “검토 초안 저장됨 · 확정 견적 유지” / “확정 견적에 반영됨”으로 구분한다. 다른 편집 영역이 더 최신 수정본을 저장하면 오래된 완료 안내는 숨긴다.
4. AI 실패를 요청 형식, 인증/접근, 모델/경로, 응답 생성, 제공자 한도, 일시적 장애로 구분한다. 실행 기록에서 실제 차감량을 표시하며, 확인 불가는 0으로 추정하지 않는다. 수동 검토 버튼은 관련 영역을 펼치고 포커스를 이동한다. 재시도 가능한 경우에만 명시적 새 실행 버튼과 예상 비용을 제공한다. 자동 유료 재호출은 추가하지 않았다.

## 검증

- Backend 기본 테스트: 45 통과, DB 전용 6개는 기본 명령에서 건너뜀.
- Frontend 테스트: 14 통과. 실패 유형/차감량/비용 안내의 서버 렌더링 회귀 포함.
- 격리 로컬 PostgreSQL 통합 테스트: 14 통과. 지도 추가 승인과 제외 해제, 과거 승인본 불변, 견적 미통과 후보의 확정 금액 보존, 이후 확정 반영, 실패 미차감/예약 해제 확인.
- 최종 Backend 전체 테스트를 격리 DB와 함께 실행: 59 통과, 건너뜀 0개. Frontend 14개를 합쳐 총 73개 통과.
- Frontend/Backend 타입 검사, 린트, production build 통과.
- Chrome + 로컬 두 서버 + 격리 DB: 모의 400 실패 안내 → 수동 입력 펼침/포커스 → 미통과 견적 조정 초안 저장 → 근거/구조 보완 → 경고 제거/확정 금액 변경 → 오래된 완료 메시지 제거 확인.
- 브라우저 검증 동안 실패 실행 1개, 미차감, 수동 검토·재검증의 추가 AI 실행 없음 확인. 제공자 호출은 로컬 모의 응답으로 대체했으며 실제 Groq 요청은 보내지 않았다.

화면 증거는 Git 제외 경로 `Frontend/test-results/ui/ux-refinements-*.png`에 보존한다.

## 범위와 한계

- 운영 DB, 배포 환경변수, 인증 정책, 모델 선택, Credit 정책은 변경하지 않았다. DB 마이그레이션이나 신규 의존성은 없다.
- 실제 Groq/Vercel 운영 환경 검증, 커밋·푸시·배포는 수행하지 않았다.
- 과거 승인 문서를 소급 수정하지 않는다. 새 승인 버전부터 포함 항목과 외부 연동 목록이 함께 반영된다.
- 검증기의 의미 판별은 구현된 규칙 범위에 한정된다. 같은 페이지라는 서술만으로 모든 경고를 영구 면제하지 않는다.
- 기존 PostgreSQL 어댑터에서 동시 `client.query()` 사용에 대한 deprecation 경고가 발생한다. 이번 테스트의 실패 원인은 아니며, 어댑터/트랜잭션 동시 쿼리 정리는 이번 UX 변경 범위에 포함하지 않았다.
