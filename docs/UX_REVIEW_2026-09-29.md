# ScopeFlow UX / 업무 흐름 검수

검수 기준: 제공된 「ScopeFlow UX / 페이지 구조 / 이동 흐름 검수 명세서」.
기존 밝은 배경, 초록색 강조, 카드와 사이드바 디자인을 유지하면서 프론트·백엔드를 함께 수정했다.

## 결과 요약

격리된 테스트 DB와 로컬 프론트·백엔드에서 다음 흐름을 실제 브라우저로 확인했다.

프로젝트·고객 생성 → 원문 요청 → AI 분석 초안 검토 → 질문 검토·공유 → 고객 답변 → 요구사항 확정 → 단가 설정 → AI 작업량 검토·금액 조정 → Scope v1.0 → 고객 승인 → 추가 요청 비교·담당자 검토 → 고객 변경 승인 → Scope v1.1.

기존 개발·운영 DB에는 마이그레이션을 적용하지 않았다. **일반 실행·배포 전에 아래 DB 적용 절차가 필요하다.** 커밋·푸시·배포는 수행하지 않았다.

## 실제 브라우저 검증

- 로컬 테스트 계정을 API로 생성한 뒤 로그인 UI와 Workspace 생성부터 시작했다. 운영 계정·실제 고객 데이터는 사용하지 않았다.
- 실제 Groq로 최초 분석, 질문, 요구사항, 견적, 변경 비교를 실행했다. 생성된 초안은 반영 전까지 확정 데이터와 분리된다.
- 분석 초안 생성 후 새로고침해 유지되는지 확인하고, 내용을 수정해 반영했다. 고객 질문 8개 답변과 내부 화면 반영을 확인했다.
- 미설정 단가 안내 → 단가 저장 → 원래 프로젝트의 견적 화면 복귀를 확인했다.
- AI 작업 시간을 수정하고 최종 금액을 조정했다. Scope의 수동 입력 기간 25일도 보존됐다.
- 고객 Scope 승인 후 수정 UI가 사라지고, 고객 링크 새로고침 시 v1.0 승인 완료가 유지됐다.
- 실제 AI가 `기존 범위 포함`으로 판정하면서 추가 기능·비용도 제안한 사례가 나왔다. 서버가 모순된 검토 확정을 거부했고, 담당자가 판정·근거·시간·금액·일정을 수정한 후 승인 요청할 수 있었다.
- 변경 승인으로 v1.1이 생성됐다. v1.0은 25일·14,000,000원, v1.1은 28일·15,500,000원으로 각각 유지됐다. v1.0에는 신규 후기 기능이 없고 v1.1에만 포함됐다.
- 버전 링크 이동과 브라우저 뒤로가기, 승인 결과 새로고침, 프로젝트 필터의 빈 결과와 기본 목록 복구를 확인했다.
- 오류 화면의 ‘다시 시도’ 버튼으로 정상 화면에 복귀했다. AI 대기·저장 대기 중 버튼 비활성화와 안내 문구도 확인했다.

## DB 적용 및 실행 전 주의

추가 마이그레이션: `Backend/prisma/migrations/0002_workflow_review/migration.sql`.

- `projects.aiDrafts` JSONB 컬럼 추가
- `requirements.status`와 허용 상태 CHECK 추가. 기존 요구사항은 CONFIRMED로 유지

실제 사용할 환경의 DB가 맞는지 먼저 확인한 뒤 Backend 폴더에서 실행한다. 자격 증명이나 `.env` 값은 문서·Git에 복사하지 않는다.

```powershell
npm run db:deploy
npm run db:generate
```

그 다음 Backend와 Frontend를 각각 실행한다. 운영 배포 시에는 운영 DB에도 같은 migration을 배포 절차에서 적용해야 한다. seed나 reset은 필요하지 않다.

검수용 별도 DB만 생성·사용·삭제했다. 테스트 서버와 브라우저 탭도 종료했으며, 기존 사용자 개발 서버는 종료하지 않았다. 삭제된 검수용 가상 데이터는 보관하지 않았고 스크립트·테스트로 다시 생성할 수 있다.

## 범위와 남은 유의점

- 생성된 AI 초안과 반영 완료 결과는 DB에 보존된다. 아직 저장하지 않은 폼 편집 내용에 대한 자동저장 기능을 추가한 것은 아니다.
- 실제 AI 판정은 틀릴 수 있다. 담당자 검토와 서버 검증을 건너뛰지 않도록 구현했다.
- pg의 다음 메이저 버전 관련 SSL/동시 query 경고가 있었으나 현재 검사 실패는 아니었다. 의존성 업그레이드 시 별도 확인한다.
- Next.js·React 검수 지침에 따라 설치된 버전의 오류 복구 규약, 요청별 조회 재사용, 폼 라벨과 중복 제출 방지를 확인했다. 새 UI 프레임워크나 전면 재설계는 도입하지 않았다.
- 운영 Vercel 배포와 운영 DB 검증은 이번 작업에 포함하지 않았다.
